# 《让敏感文件不出电脑：基于 AI PC 的本地隐私数据检查 Skill》需求文档

文档版本：V1.0（Skill 当前版本：V0.3）
项目英文名：**Local Privacy Inspector Skill**
项目类型：AI PC Agent Skill / 本地隐私数据检查工具
适用场景：文件外发前检查、代码上传前检查、合同共享前检查、简历投递前检查、项目资料归档前检查

---

# 1. 项目概述

## 1.1 项目名称

**让敏感文件不出电脑：基于 AI PC 的本地隐私数据检查 Skill**

简称：

**本地隐私数据检查 Skill**

英文名：

**Local Privacy Inspector Skill**

---

## 1.2 一句话定位

一个运行在 AI PC 本地的隐私数据检查 Skill，帮助用户在文件外发、上传或共享前，检查指定文件或文件夹中是否包含手机号、身份证号、邮箱、API Key、Token、数据库连接串、合同金额、客户名称等敏感信息，并生成默认脱敏的风险报告。

---

## 1.3 项目核心价值

本项目的核心不是“扫描文件”，而是：

> **让用户在不上传原始文件的前提下，完成本地隐私风险检查。**

它解决的是一个非常具体的问题：

很多文件在发送、上传、共享、归档之前，用户并不知道里面是否包含敏感信息。

例如：

* 合同中有客户名称、联系人手机号、合同金额
* 简历中有身份证号、详细住址
* 代码项目中有 `.env`、API Key、数据库密码
* 会议纪要中有内部项目代号、预算金额、客户信息
* Excel 表格中有客户名单、手机号、邮箱

这些内容如果直接上传云端工具进行检测，反而会增加新的隐私泄露风险。

因此，本 Skill 强调：

```text
原始文件不上传
只扫描用户指定文件或文件夹
检测结果默认脱敏
不自动修改原文件
生成本地风险报告
```

# 2. 项目背景

## 2.1 问题背景

在日常办公、项目交付、软件开发、资料归档和内容发布中，用户经常需要处理大量文件。

常见文件包括：

```text
合同
报价单
会议纪要
客户清单
项目资料
简历
申请材料
代码项目
配置文件
技术文档
截图
PDF
Excel 表格
Word 文档
```

这些文件中可能隐藏敏感信息。

用户往往在以下场景中存在风险：

```text
准备把合同发给外部合作方
准备把代码项目上传 GitHub
准备把简历上传招聘平台
准备把项目资料发给客户
准备把会议纪要转发给非项目成员
准备把截图发到小红书、公众号或技术社区
准备把内部资料整理成公开案例
```

很多时候，用户不是故意泄露，而是没有意识到文件中存在敏感字段。

---

## 2.2 传统方案的问题

传统方案通常有三种：

### 方案一：人工检查

问题：

```text
效率低
容易遗漏
不能处理大量文件
无法稳定识别 API Key、Token、数据库连接串等技术敏感信息
```

---

### 方案二：云端工具检查

问题：

```text
需要上传文件
原始敏感信息可能先暴露给第三方服务
不适合合同、客户资料、代码配置、内部会议纪要等文件
```

---

### 方案三：安全软件全盘扫描

问题：

```text
权限较重
配置复杂
不适合轻量级办公场景
用户很难控制扫描范围
不适合参赛 Demo 和个人用户使用
```

---

## 2.3 本项目解决思路

本项目采用 AI PC 本地 Agent Skill 方式实现：

```text
用户选择文件或文件夹
        ↓
本地解析文件内容
        ↓
本地识别敏感信息
        ↓
本地风险分级
        ↓
默认脱敏展示
        ↓
生成本地检查报告
```

整个过程中，原始文件不上传云端，检测范围由用户主动指定。

# 3. 产品定位

## 3.1 产品定位

本项目定位为：

> 面向个人用户、办公用户和开发者的 AI PC 本地隐私数据检查 Skill。

它不是企业级 DLP 系统，也不是杀毒软件，也不是全盘安全扫描器。

它是一个轻量级、本地化、可复用的 Agent Skill。

---

## 3.2 产品边界

## 做什么

本项目做：

```text
检查用户指定文件
检查用户指定文件夹
识别常见敏感信息
识别开发者密钥风险
识别企业办公敏感字段
识别个人隐私字段
生成脱敏风险报告
给出处理建议
```

---

## 不做什么

MVP 阶段不做：

```text
不扫描整台电脑
不后台自动扫描
不实时监控文件变化
不自动删除文件
不自动修改原始文件
不自动上传报告
不自动提交 Git
不读取聊天记录
不读取浏览器缓存
不扫描系统目录
不做企业级权限审计
不替代法律合规判断
```

# 5. 核心使用场景

## 5.1 场景一：合同外发前检查

### 用户痛点

合同文件中经常包含：

```text
甲方名称
乙方名称
联系人
手机号
合同金额
统一社会信用代码
项目编号
付款信息
```

如果合同被转发给错误对象，可能造成客户信息和商业信息泄露。

### 用户操作

```text
用户选择 contract_sample.docx
调用本地隐私数据检查 Skill
Skill 本地解析 Word 文档
识别合同金额、手机号、客户名称等字段
生成脱敏报告
```

### 输出示例

```text
文件：contract_sample.docx
风险等级：中风险

发现内容：
1. 客户名称：南京****科技有限公司
2. 合同金额：¥**** 元
3. 联系人手机号：138****5678
4. 统一社会信用代码：9132************

建议：
1. 外发前确认客户名称是否需要保留
2. 联系人手机号建议脱敏
3. 合同金额如用于公开材料，建议替换为区间或删除
```

---

## 5.2 场景二：代码上传前检查

### 用户痛点

开发者经常把项目上传到 GitHub、GitLab 或交给同事。

风险文件包括：

```text
.env
.env.production
config.yaml
secrets.json
application-prod.yml
settings.py
docker-compose.yml
```

这些文件可能包含：

```text
API Key
AccessKey
SecretKey
Token
数据库连接串
密码字段
服务器 IP
```

### 用户操作

```text
用户选择项目文件夹
Skill 扫描指定文件夹
跳过 node_modules、.git、dist、build 等目录
识别密钥类风险
输出高风险文件清单
```

### 输出示例

```text
扫描路径：/Users/demo/my-project
风险等级：高风险

高风险文件：
1. .env
   - 发现 API Key：sk-********abcd
   - 发现数据库连接串：mysql://user:****@127.0.0.1:3306/demo
   - 发现密码字段：DB_PASSWORD=****

2. config.yaml
   - 发现 AccessKey：AKIA********1234
   - 发现 SecretKey：********abcd

建议：
1. 将 .env 加入 .gitignore
2. 删除代码中的明文密钥
3. 使用环境变量或密钥管理服务
4. 如密钥已经上传过公开仓库，建议立即轮换
```

---

# 6. 功能需求

# 6.1 文件选择功能

## 功能描述

用户可以指定：

```text
单个文件路径
单个文件夹路径
```

Skill 只处理用户明确指定的路径。

---

## 输入方式

支持自然语言输入：

```text
帮我检查这个文件有没有敏感信息：/Users/demo/resume.pdf
```

```text
请扫描这个文件夹：/Users/demo/project_docs
```

---

## 功能规则

```text
如果输入是文件，则只检查该文件
如果输入是文件夹，则扫描该文件夹及其子文件夹
如果路径不存在，返回错误提示
如果路径无权限访问，返回权限提示
如果文件类型不支持，返回跳过原因
```

---

# 6.5 风险分级功能

## 功能描述

系统根据敏感信息类型、数量、文件类型和上下文进行风险分级。

---

## 风险等级

```text
高风险
中风险
低风险
提示信息
```

---

## 高风险判定规则

符合以下任一条件，判定为高风险：

```text
发现 API Key
发现 SecretKey
发现 AccessKey
发现 Token
发现数据库连接串
发现 SSH 私钥
发现身份证号
发现银行卡号
发现 .env 文件中的密码字段
发现生产环境配置文件中的密钥
```

---

## 中风险判定规则

符合以下任一条件，判定为中风险：

```text
发现手机号
发现合同金额
发现客户名称
发现项目编号
发现联系人信息
发现服务器 IP
发现预算金额
发现内部项目代号
```

---

## 低风险判定规则

符合以下任一条件，判定为低风险：

```text
发现普通邮箱
发现普通姓名字段
发现非完整地址
发现公开公司名称
发现普通联系电话字段
```

---

## 提示信息

适合提醒但不一定构成风险的内容：

```text
文件名中包含 confidential
文件名中包含 internal
文件名中包含 draft
文件名中包含 final
文件名中包含 backup
```

# 7. Agent Skill 设计

## 7.1 Skill 总体流程

```text
用户输入文件或文件夹路径
        ↓
Agent 理解任务
        ↓
确认扫描范围
        ↓
调用 scan_files 工具
        ↓
调用 extract_text 工具
        ↓
调用 detect_sensitive_info 工具
        ↓
调用 classify_risk 工具
        ↓
调用 mask_sensitive_info 工具
        ↓
调用 generate_report 工具
        ↓
返回本地隐私风险报告
```

---

## 7.2 Agent 职责

Agent 负责：

```text
理解用户自然语言请求
判断用户输入的是文件还是文件夹
调用对应工具
汇总检测结果
生成自然语言解释
给出风险处理建议
```

Agent 不负责：

```text
直接读取未授权目录
绕过系统权限
自动修改文件
自动删除文件
自动上传文件
```

---

## 7.3 工具拆分

### 工具一：文件扫描工具

```python
scan_files(path: str) -> List[FileItem]
```

功能：

```text
判断路径类型
遍历指定目录
过滤不支持文件
跳过依赖目录和系统目录
返回待处理文件列表
```

---

### 工具二：文本抽取工具

```python
extract_text(file_path: str) -> ExtractResult
```

功能：

```text
根据文件类型提取文本
返回文本内容
返回解析状态
返回解析方式
```

---

### 工具三：敏感信息检测工具

```python
detect_sensitive_info(text: str, file_path: str) -> List[Finding]
```

功能：

```text
识别个人敏感信息
识别企业敏感信息
识别开发者密钥
识别文件风险特征
```

---

### 工具四：风险分级工具

```python
classify_risk(findings: List[Finding], file_meta: FileItem) -> FileRiskSummary
```

功能：

```text
根据命中类型和文件特征计算风险等级
输出风险原因
生成处理建议
```

---

### 工具五：脱敏工具

```python
mask_sensitive_value(value: str, sensitive_type: str) -> str
```

功能：

```text
对手机号、身份证号、邮箱、密钥、金额、客户名称等字段进行脱敏
```

---

### 工具六：报告生成工具

```python
generate_report(results: List[FileRiskSummary], output_format: str) -> str
```

功能：

```text
生成 Markdown 或 JSON 报告
输出报告路径
```
