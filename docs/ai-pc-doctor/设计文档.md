**Agent 环境：** WorkBuddy / Qoder / TRAE Work

# 1. 项目背景

随着 AI PC、Intel Core Ultra、NPU、OpenVINO 等技术逐渐普及，越来越多用户希望在个人电脑上直接运行大语言模型、Embedding 模型、OCR、ASR、视觉模型等本地 AI 能力。

但普通用户在真正开始部署时，往往会遇到一系列问题：

```text
我的电脑算不算 AI PC？

CPU 是什么型号？
有没有 GPU？
有没有 NPU？

OpenVINO 安装了吗？
OpenVINO 能不能识别我的 GPU / NPU？

驱动有没有安装正确？

我的电脑到底能跑多大的模型？
1B / 3B / 7B / 14B 哪个适合？

模型应该跑 CPU、GPU 还是 NPU？

实际推理速度是多少？
首 Token 要等多久？
每秒能生成多少 Token？

INT4、INT8、FP16 应该怎么选？
```

目前这些问题通常需要用户分别查询：

* 操作系统信息
* CPU / GPU / NPU 型号
* Intel 驱动
* OpenVINO 环境
* Python 环境
* 模型量化方案
* Benchmark 工具
* LLM 性能指标

整个过程对普通用户门槛较高。

因此，本项目希望将这一完整流程封装成一个可被 WorkBuddy 等生产力 Agent 调用的 AI PC Skill。

# 4. 核心设计原则

## 4.1 本地检测

所有设备信息、性能测试和 Benchmark 均在当前 PC 本地执行。

不依赖云端硬件检测。

---

## 4.2 数据来自真实环境

禁止由 LLM 推测：

```text
CPU 型号
GPU 型号
NPU 是否存在
OpenVINO 是否安装
OpenVINO 可用 Device
模型运行性能
```

这些必须来自：

```text
操作系统
Python
OpenVINO Runtime
Benchmark 工具
真实推理结果
```

LLM 只负责：

> 理解、解释和建议。

---

## 4.3 理论能力与实测能力分离

报告必须区分：

### 理论支持

例如：

```text
系统存在 Intel NPU
```

与：

### 实测支持

```text
OpenVINO 能够成功在 NPU 编译并运行指定模型
```

不得把：

> 检测到硬件

等价为：

> 模型一定能运行。

---

## 4.4 Benchmark 优先于纸面配置

配置只能回答：

> 理论上能不能运行。

Benchmark 才能回答：

> 实际体验怎么样。

因此本项目采用：

```text
System Probe
+
Runtime Probe
+
Smoke Test
+
Benchmark
```

四层验证方式。

# 19. Smoke Test

仅仅检测到：

```text
GPU
NPU
```

是不够的。

必须执行一次最小模型推理测试。

流程：

```text
Load Small Model
↓
Compile Model
↓
Inference
↓
Validate Output
```

状态：

```text
PASS
FAIL
UNSUPPORTED
SKIPPED
```

例如：

```json
{
  "device": "NPU",
  "compile": "PASS",
  "inference": "PASS"
}
```

## Smoke Test 注意事项（尤其 NPU）

- Smoke Test 模型必须**随仓库分发**（如 MNIST-8，约 26KB），保证离线可跑，不依赖网络下载。
- **分设备选型**：CPU / GPU 可用常规轻量模型；NPU 只支持**静态 Shape**，必须使用静态输入的模型，动态 Shape 模型在 NPU 上编译会失败——这属于预期行为，应记为 `UNSUPPORTED` 而非 `FAIL`。
- **NPU 编译超时**：NPU 首次编译耗时远长于 CPU / GPU（可能数十秒），必须为 NPU Compile Test 设置独立且更长的超时（建议 ≥ 120 秒），避免误判为失败。
- NPU 编译失败后，可在报告中提示"驱动版本与 OpenVINO NPU 插件不匹配"的可能原因。

# 24. LLM Benchmark 指标

必须至少包括：

## Model Load Time

模型从磁盘加载完成所需时间。

---

## TTFT

Time To First Token。

代表：

> 用户多久能够看到第一个 Token。

单位：

```text
ms
```

---

## TPOT

Time Per Output Token。

表示：

> 首 Token 之后，平均生成一个 Token 需要多久。

单位：

```text
ms/token
```

---

## Throughput

```text
tokens/s
```

代表模型生成速度。

---

## Generation Duration

整个生成过程耗时。

---

## Input Tokens

Prompt Token 数量。

---

## Output Tokens

最终生成 Token 数量。

# 27. Model Capacity Estimator

这是区别于普通 Benchmark 工具的重要模块。

目标：

> 根据当前机器资源估算适合运行多大的模型。

---

# 28. 模型容量估算逻辑

基础模型权重估算：

```text
FP32
约 4 Bytes / 参数

FP16 / BF16
约 2 Bytes / 参数

INT8
约 1 Byte / 参数

INT4
约 0.5 Byte / 参数
```

但实际部署需要额外考虑：

```text
Runtime Overhead
KV Cache
Context Length
Tokenizer
Runtime Buffer
OS Memory
其他程序内存
```

因此：

> 禁止将模型权重大小直接等同为运行内存。

---

# 29. 推荐等级

统一使用：

```text
EXCELLENT
RECOMMENDED
LIMITED
NOT_RECOMMENDED
UNKNOWN
```

例如：

| 模型规模     | 推荐              |
| -------- | --------------- |
| 1B       | EXCELLENT       |
| 3B       | EXCELLENT       |
| 7B INT4  | RECOMMENDED     |
| 14B INT4 | LIMITED         |
| 32B      | NOT_RECOMMENDED |

```text

```

| ------------ | -: |

| NPU 能力       | 20 |
| 内存           | 15 |

---

# 34. 分数解释

```text
90-100
Excellent AI PC

75-89
AI Ready

60-74
Basic Local AI

40-59
Limited

0-39
Not Recommended
```

但报告必须强调：

> Readiness Score 是工具内部综合评价，不代表 Intel 官方认证。

## 评分口径限制

- **非目标平台不评分**：macOS、非 Intel 平台走 Graceful Degradation，只输出环境说明，**不输出 Readiness Score**，避免产生误导性低分。
- 权重为初始经验值，需在至少 3 类真机（纯 CPU 老机器 / 无 NPU 的 Ultra 一代 / Ultra 二代 AI PC）实测后校准。

# 46. 修复建议

建议只给：

```text
诊断建议
```

不能：

```text
自动安装驱动
自动修改系统
自动升级系统
```

MVP 不执行高风险系统操作。

## 环境未就绪引导流程

当检测到 Python / OpenVINO 缺失或版本过低时，Skill **不自动安装**，而是走引导流程：

```text
检测到环境缺失
↓
报告中标记 OPEN_VINO_NOT_INSTALLED（severity: error）
↓
输出引导步骤：
  1. 建议创建虚拟环境：python -m venv .venv
  2. 安装：pip install openvino（可提示使用国内 PyPI 镜像）
  3. 安装完成后重新运行 doctor
↓
由 Agent 向用户解释并征得同意后，方可代为执行安装命令
```

即：安装动作可以由 Agent 在用户同意后执行，但**安装决策必须来自用户**，且只安装明确声明的依赖（openvino 及官方生态包）。

# 49. 网络设计

V0.1 支持两种情况。

### Offline

如果测试模型已存在：

```text
完整离线运行。
```

### Online Optional

用户需要测试模型但本地没有时：

```text
允许用户确认后下载。
```

核心环境检测不依赖网络。

## 模型来源策略

- **Smoke Test 模型**：随仓库分发（MNIST-8，约 26KB），保证离线、零下载完成冒烟测试。
- **Benchmark 模型**：默认从 **ModelScope 镜像**下载（国内网络环境稳定），HuggingFace 作为可选备用源，通过环境变量或 CLI 参数切换。
- **本地缓存**：所有下载的模型统一放入 `models/` 缓存目录，已存在的模型直接使用，不重复下载。
- **下载确认**：任何 > 1GB 的模型下载必须先征得用户同意（见安全设计）。
- GenAI Benchmark 默认模型建议：Qwen 0.5B INT4（约 300MB），兼顾下载速度与演示效果。

真实推理速度是多少？
